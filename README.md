# Автоматическое создание дерева сертификатов

Лабораторная работа №1 по инфраструктуре открытых ключей (PKI). Проект формирует трёхуровневую цепочку сертификатов X.509 средствами OpenSSL: корневой удостоверяющий центр ВШЭ, промежуточный удостоверяющий центр учебной группы и сертификат студента для защищённой электронной почты.

```text
HSE RootCA                 rootca.crt
└── УЦ учебной группы      groupmca.crt
    └── Студент            usercert.crt
```

Корневой сертификат самоподписанный. Сертификат группы подписывается закрытым ключом корня, сертификат студента — закрытым ключом группы.

## Состав проекта

| Файл | Назначение |
| --- | --- |
| `do_it.bat` | Генерация ключей, запросов и сертификатов, сборка PKCS#12 и импорт в Windows. Основан на шаблоне преподавателя. |
| `openssl.cnf` | Параметры OpenSSL и секции расширений `v3_ca`, `v3_mca`, `usr_cert`. |
| `run-lab.cmd` | Запуск `do_it.bat` с локально настроенным PATH для OpenSSL. |
| `openssl.cmd` | Вызов установленного OpenSSL из терминала проекта. |
| `.gitignore` | Исключения для закрытых ключей, PKCS#12 и промежуточных файлов. |

## Требования

- Windows и командный интерпретатор `cmd.exe` для `.bat`/`.cmd`.
- OpenSSL. Локальные обёртки настроены на `C:\Program Files\Git\usr\bin\openssl.exe`; проверена версия 3.2.4. На другом компьютере путь в обёртках нужно изменить.
- Утилита Windows `certutil` для импорта сертификатов. Исходный скрипт использует хранилище компьютера, поэтому для его этапа импорта нужны права администратора.

## Генерация и параметры

Сценарий создаёт три пары ключей RSA 4096 бит. Сроки действия в исходном шаблоне: корневой сертификат — 3650 дней, промежуточный — 365 дней, пользовательский — 90 дней. Закрытые ключи зашифрованы учебным паролем `HSEPassw0rd`, контейнер `final.p12` — паролем `UserPass123`.

Поля Subject задаются параметром `-subj` в `do_it.bat`. Расширения сертификатов задаются в `openssl.cnf`:

- `v3_ca` — корневой УЦ, `CA:TRUE` и право подписи сертификатов.
- `v3_mca` — УЦ группы, `CA:TRUE`, право подписи сертификатов и `pathlen:0`, запрещающий нижележащие промежуточные УЦ.
- `usr_cert` — студент, `CA:FALSE`, шифрование ключей и данных, назначение `emailProtection`.

Задание предусматривает персонализацию Subject, добавление `subjectKeyIdentifier` / `authorityKeyIdentifier` и ограничение пространства имён через `nameConstraints`.

```powershell
cd C:\Dima\PKI\Lab_01

```

После персонализации и настройки расширений:


Скрипт перезаписывает одноимённые ключи и сертификаты и выполняет импорт `final.p12` через `certutil`. До запуска необходимо завершить настройку и проверить команды импорта.

## Проверка

Просмотр параметров и проверка цепочки:

```powershell
.\openssl.cmd x509 -in rootca.crt -noout -text
.\openssl.cmd x509 -in groupmca.crt -noout -text
.\openssl.cmd x509 -in usercert.crt -noout -text
.\openssl.cmd verify -CAfile rootca.crt -untrusted groupmca.crt usercert.crt
```

Ожидаемый результат проверки цепочки: `usercert.crt: OK`. Дополнительно проверяются Subject/Issuer, назначения сертификатов, соответствие AKI дочернего сертификата SKI издателя и ограничения имён.

После импорта в Windows вкладка «Путь сертификации» пользовательского сертификата должна показывать три уровня без ошибок. Хранилища текущего пользователя (`certmgr.msc`) и компьютера (`certlm.msc`) различаются.
